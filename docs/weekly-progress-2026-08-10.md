# ReTrace-ASR 本周工作进展（2026-08-10）

## 本周目标

围绕“后文语义触发、历史音频复核、稀疏 Agent 调度”的流式对话 ASR 修订问题，完成可运行的 ReTrace 原型、前端方法展示和 ICASSP 论文草稿扩写；同时明确哪些结论已经由工程验证，哪些仍需真实音频实验验证。

## 已完成工作

### 1. 核心算法与系统链路

- 实现了不可变 ASR Turn、时间戳、置信度/候选信息与追加式修订事件。
- 实现 local-first 路由：优先用后文候选复现、近形冲突等本地规则产生修订提案。
- 实现局部历史音频复听：根据目标 span 在 Turn 中的位置裁剪带上下文的音频窗口，而不是重跑整段历史录音。
- 实现强音频门控：候选必须是音频最高分、分数至少为 `0.70`、并与第二名相差至少 `0.10` 才能自动提交。
- 实现弱证据升级：当候选仍是音频第一名且分数至少 `0.55` 时，才调用一次 DeepSeek，在当前候选与证据包内做受限裁决。
- 实现退化 ASR 恢复支路：对重复填充词等无有效候选的退化 Turn，扩大局部窗口进行开放式重转写，并单独记录 resolver 路径。
- 保留符号化实体回退路径，但明确其是语义/实体证据，不应与音频验证结果混为一谈。

### 2. Agent 成本控制与可审计性

- DeepSeek 不再按 Turn 无差别调用，只在 deferred candidate、跨文字体系品牌线索等稀疏触发条件下介入。
- 每条修订保存目标 Turn、证据 Turn、局部音频区间、候选分数、resolver、理由和替换文本。
- 前端已更新为展示当前会话、修订事件、候选证据和自动修订状态；Qwen-Omni 与 DeepSeek 的服务端集成仍保留。

### 3. 论文与文档

- 独立论文目录：`/Users/panyibo/ReTrace-ICASSP-Paper`。
- 采用 IEEE conference (`IEEEtran`) 格式，而非 KDD 的 `acmart` 格式。
- 论文已扩展为四页 PDF，新增：问题定义、resolver 路径、强/弱音频门控、复杂度与成本、数据构建、标注协议、统计检验、消融设计、案例与失败模式。
- 论文结果表保持空值（`--`），没有虚构 CER/WER、准确率或成本结果。
